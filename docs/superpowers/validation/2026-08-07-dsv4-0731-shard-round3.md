# Round 3: the two rounds contradict each other — resolve that before eliminating anything

**The round-2 elimination does not hold.** Its data disagrees with round 1 about
the same weight on the same cluster, and every weight it probed is unchanged
across the shard — including a control that shards a different axis.

## The contradiction

| | `attn.wo_a.weight` before | after |
|---|---|---|
| Round 1 | `(8192, 1024)` | `(8192, 512)` — halved |
| Round 2 | `(8192, 1024)` | `(8192, 1024)` — unchanged |

Both rounds claim to describe layer 0 on the live two-rank cluster. They cannot
both be right.

Round 2 is not a near miss, either. Under a real `N=2` shard, four distinct
things should move, on two different axes:

| Weight | Sharding | Expected change |
|---|---|---|
| `attn.wo_a` | `sharded_to_all` | input axis `1024 -> 512` |
| `shared.down_proj` | `sharded_to_all` | input axis `512 -> 256` |
| `switch.down_proj` | `sharded_to_all` | input axis `256 -> 128` |
| `switch.gate_proj` | `all_to_sharded` | **output** axis `2048 -> 1024` |

Round 2 reports **none** of the four changing. A `scales`-vs-`weight`
inconsistency could not produce that, and neither could a correct shard. Nothing
was sharded in that run.

## Why this is ambiguous, and that part is my fault

The round-2 helper I wrote dropped the `rank=X/Y` and `n_heads` fields that
round 1 logged. So the run cannot be checked for `world_size`, and the report
gives a single set of numbers rather than one per rank — where round 1 explicitly
showed `Rank 0/2` and `Rank 1/2`. Nothing in the output can distinguish the two
live hypotheses below. That is a defect in the instrumentation, not in the
investigation.

## Two hypotheses, and the second is a strong root-cause candidate

**H1 — round 2 ran with `world_size=1`.** A single-process run makes
`_shard_v4_attention_heads(attn, 1, 0)` slice nothing and
`sharded_to_all_linear_in_place` shard into one piece. Every ratio then matches
trivially and the elimination is void. This is the same trap that invalidated the
original `test_v4_real_model_attn_mismatch.py`, which is reason enough to suspect
it. If so: re-run under the cluster and the round-2 question is still open.

**H2 — sharding genuinely is not being applied on the cluster, while the
collective wrappers still are.** This would explain the whole defect.
`DeepseekV4ShardingStrategy.shard_model` installs two reducers regardless of
whether the weight slicing took effect:

```python
layer.attn.wo_b = _AllSumLinear(layer.attn.wo_b, self.group)
...
wrapped = ShardedMoEV4(ffn); wrapped.sharding_group = self.group
```

`_AllSumLinear.__call__` all-sums its input then applies `wo_b`.
`ShardedMoEV4.__call__` all-sums the FFN output. If the weights are unsharded,
each rank computes the **complete** attention output and the **complete** FFN
output, and the all-sum then **doubles both, at every one of 43 layers**.

Doubled activations compounding through 43 layers produce output that is
incoherent, deterministic, and never reaches EOS. That is precisely the observed
symptom, and it also explains why the model runs at full speed without raising:
no shape is ever wrong, the values are simply twice what they should be.

H2 also fits the earlier evidence better than anything eliminated so far. It
would not be caught by `test_tp_bit_exact.py` if that test compares a
deliberately-constructed sharded model rather than the production shard path.

## What round 3 must log

Replace the round-2 helper with this. The additions over round 2 are
`world_size`, `rank`, `n_heads`, and the unpacked input width implied by each
array — so a single line is self-sufficient and no cross-referencing is needed.

```python
def _log_shard_probe(
    label: str,
    module: nn.Module,
    stage: str,
    world_size: int,
    rank: int,
    n_heads: int | None = None,
) -> None:
    """Self-contained shard probe. Every field needed to interpret the line is
    on the line, because round 2 omitted world_size and its result could not be
    told apart from a single-process no-op."""
    weight = module.get("weight") if isinstance(module, nn.Module) else None
    if not isinstance(weight, mx.array):
        logger.info(f"shard-probe [{stage}] N={world_size} r={rank} {label}: not quantized")
        return
    scales = module.get("scales")
    bits = getattr(module, "bits", None)
    group_size = getattr(module, "group_size", None)

    w_trailing = int(weight.shape[-1])
    s_trailing = int(scales.shape[-1]) if isinstance(scales, mx.array) else None
    in_from_weight = None if not bits else w_trailing * (32 // int(bits))
    in_from_scales = None if not (s_trailing and group_size) else s_trailing * int(group_size)

    logger.info(
        f"shard-probe [{stage}] N={world_size} r={rank} {label}: "
        f"n_heads={n_heads} weight={tuple(weight.shape)} "
        f"scales={None if not isinstance(scales, mx.array) else tuple(scales.shape)} "
        f"in_from_weight={in_from_weight} in_from_scales={in_from_scales} "
        f"arrays_agree={in_from_weight == in_from_scales} "
        f"mode={getattr(module, 'mode', None)} bits={bits} group_size={group_size}"
    )
```

Call it with `self.N` and `self.group.rank()`, and pass
`layer.attn.n_heads` for the attention weights. Probe layer 0 only, at the same
three points as round 1 (`before`, `heads-sharded`, `after`), plus the four MoE
weights before and after.

## Reading round 3

| Observation | Meaning |
|---|---|
| `N=1` on the log lines | Not a cluster run. Round 2's conclusion is void; re-run properly. Nothing else in the output means anything. |
| `N=2` and all four weights unchanged | **H2 confirmed.** Sharding is not being applied while the all-sum wrappers are, so every attention and FFN output is doubled at every layer. Find why `shard_inplace` is a no-op here — check whether it mutates in place at all for these module types, or returns a new array that must be rebound. |
| `N=2`, weights change as the table above predicts, `arrays_agree=True` throughout | Sharding is correct end to end. The structural search really is exhausted; move to `sanitize()`. |
| `N=2`, weights change but `arrays_agree=False` after | The round-2 hypothesis, now properly observed. `_shard_quantized_rows` is the pattern to follow. |
| `n_heads` still 64 after `heads-sharded` | Head sharding is a no-op too, which narrows H2 further. |

## Cheap independent confirmation of H2

If the round-3 log shows `N=2` with unsharded weights, confirm the doubling
directly rather than by inference: temporarily bypass one reducer — return
`self.inner(x)` from `_AllSumLinear.__call__` without the `all_sum` — and see
whether output coherence changes. Not a fix, a probe. If a single-rank-worth of
attention output produces more coherent text than the doubled version, H2 is
settled.

Alternatively, log the L2 norm of the attention output before and after the
`all_sum` on rank 0 for one token. A ratio of exactly 2.0 confirms doubling; a
correct sharded setup gives something other than 2.0 because each rank
contributes a genuine partial.

## Also worth noting from the round-2 data

The mode and quantization parameters are now known and self-consistent, which is
useful regardless: `attn.wo_a` and `shared.down_proj` are **mxfp8** with
`bits=8, group_size=32`, while `switch_mlp` is **mxfp4** with
`bits=4, group_size=32`. Every array's implied unpacked input width agrees
between `weight` and `scales` (4096, 2048, 2048, 4096 respectively), and
`attn.wo_a`'s 4096 equals the **unsharded** `group_feat` exactly.

Two incidental points. My predicted `group_size=64` was wrong — the weights carry
32 — and the ratio invariant absorbed that, which is what it was designed for.
And the checkpoint's top-level `quantization_config.group_size` is 64 while these
modules report 32, so quantization is per-module here; worth confirming the
post-quantize audit compares against per-module parameters rather than the
top-level ones, since my earlier notes record that `mode` mismatches are
invisible to strict loading.
